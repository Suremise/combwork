# Coordinate agents: reviews and new lanes

## Reviews and new lanes

- **Its review** depends on the project's Review option. Where an agent reviews (an agent, or an agent then you) and the project has a builder and a reviewer, run even one card as a lane (below), not `cw_start_task` on the builder alone, so Combwork wakes the reviewer when it reaches Review. Where only the user reviews, the card waits for them under For you; with no review, the review stage is skipped and the card goes straight on to its finish (How a card finishes): start no reviewer for either. A card that reaches Review outside a lane, in a project whose work is reviewed by an agent: Combwork gives it to a free reviewer of the project itself; start none.
- **A new lane** (an agent's next set of cards to build or review in a card loop, even a single card): first `cw_lane` `start` (project, builder, reviewer, cards, and `brief`), so it shows at once. **The builder's brief goes only there**, in `brief`: its role in card-loop, its cards and its reviewer, rounds and wait only if the user gave them (otherwise the lane takes the project's card-loop settings), and what this lane needs. Combwork gives it with each of the lane's cards, in the conversation that works the card; where cards are built in slots that is a new conversation in the builder's slot, which a brief sent as a prompt never reaches, so never prompt the builder with it. Combwork then starts the lane's stopped agents as the user's **Start Lane** does: a stopped builder's slot first where cards are built in slots, then each stopped agent in a new conversation with the lane's brief. Its reply says whom it started and where, or that the lane waits for a slot (its stopped agents start once one is free): never prompt an agent Combwork started. An idle builder where cards aren't built in slots gets the lane in a new conversation too (its last stays in its Sessions history), or once it is free, and the reply says so: never prompt it. Any other agent already running is left as it is, and the reply names it. A lane you update whose builder isn't running gets its builder started on it. A running builder the reply says Combwork gives its first card isn't yours to prompt (a prompt too would race Combwork's start). Only an agent the reply says to tell, or names as not started, is yours (one busy: wait until it is idle): the builder in a new conversation with one line naming its lane (`Use card-loop as the builder of lane L-12: cw_lane next names your card.`), `cw_prompt_agent` with `newConversation: true` if it is idle, `cw_start_agent` with that line if it is stopped; the reviewer with a prompt, as reviewers never work in a slot (`Use card-loop as the reviewer. Cards: AM-12. Your builder is B1.`), the same way. Not `cw_start_task`, which gives the card in the conversation the agent already has. Within a lane, keep the same conversation. Every request re-reads the whole conversation, so a short one per lane costs much less. A card made for a lane goes on it as you create it (`cw_create_task` with `lane`: the builder's name, or `{ builder, reviewer, brief }` to start its lane), never by a guessed key. To change the builder's brief, `start` again with a new `brief`; to reorder its cards, `start` again with the new list (after the card in flight, or at once with `applyNow: true`: run-lanes), never by abandoning the lane; `cw_lane` `list` shows the lanes running. Several lanes at once: the run-lanes skill.
