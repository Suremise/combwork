# Release Notes

## 0.9.3 — 2026-10-20

- **The Assistant's modes are in `.hive/modes`.** Modes were once called personas, and their files still were: each workspace's are now in `.hive/modes`, where Hive moves its `.hive/personas` folder when the workspace opens, your own modes and edits with it, and the mode you chose stays chosen. If the folder can't be moved yet (a file in it open), Hive uses it where it is and moves it next time (#1084).
- **Agent API: `personaBytes` is now `modeBytes`.** In `GET /v1/metrics`, each guidance series' `personaBytes` and `personaChars` are now `modeBytes` and `modeChars`. The old names are still sent in this release, and go in the next one (#1084).
- **Codex asks before other MCP servers' tools, as Claude Code and Copilot do.** Hive started Codex agents with the tools of every MCP server on in their project approved in advance, so a server you added ran its tools without Codex asking. Now only Hive's own `hive` tools are approved in advance, in every CLI; another server's tools follow Codex's own approval rules for the agent's mode, like its other tools: Read only and Ask for approval ask before such a call (unless the server marks the tool read-only, or you allowed it for the session or always), Approve for me leaves it to Codex's reviewer, and Full access doesn't ask. A hand-made `.hive/mcp/hive.json` (the name is Hive's own) is no longer given to sessions either.
- **The code editor uses the fixed DOMPurify.** Monaco, the Files tab's editor, ships its own copy of DOMPurify 3.4.15, which has two advisories (GHSA-p98j-92pf-mc4p, GHSA-6688-9rhm-gjv2; both need a way of sanitising Monaco doesn't use). Hive now builds Monaco with its own DOMPurify 3.4.16 instead, so the copy no longer ships and `npm audit` no longer lists it (#1141).
- **Tiles keep one size.** In the Tiles view, a tile grew when its agent started a long run (its progress bar) or had a longer reply, and shrank again after, so the tiles jumped as you read them. Every tile now has room for everything it can show and keeps that size; text too long for its line ends in an ellipsis and shows in full on hover (#1145).
- **A resumed agent isn't told of new work before Hive's tools are back.** A Claude Code session resumed (the Assistant's too) is ready a moment before Hive's tools have reconnected in it, and a message's notice typed then was a turn the agent couldn't read it in: it said its tools had disconnected, and was told again later. Hive now waits until the agent's tools have connected, at most 30 seconds (*hive tools: wait to connect* in Settings → Advanced), before it tells the agent (#865).
- **The first agent you resume after starting Hive starts sooner.** Hive tracks the processes each agent starts through a hidden PowerShell helper, which it started only when the first agent launched, so that launch (the first of a Resume All) waited about half a second for it. The helper now starts in the background as Hive reopens your workspace, and the first launch finds it running (#1155).
- **Purge what Hive keeps.** A new **Purge…** in **Project Settings → Storage** and **Settings → Workspace → Storage**, and **Purge Hive's Files…** on a session in the Sessions tab, remove everything Hive keeps for sessions: its backups of their transcripts, the archive, attachments, and what is left of deleted sessions. It lists every file and its size first, then moves exactly those to the Recycle Bin, or deletes them permanently if you choose. The coding agents' own files are never touched, running sessions are left alone, and what sessions used stays in your usage totals; a session whose only copy was Hive's is deleted, as Delete Session does, and the dialog warns you first (#1138).
- **Resuming a long session no longer makes Hive re-read its transcript.** A running agent's footer and context gauge were worked out in Hive's main process, and after a restart the first turn of a resumed session read its whole transcript again (several hundred MB for a long one), while every terminal's typing waited on the same process. They're now read in the background by the usage history's thread, which carries on from where the history left off, so a resumed 300 MB session's figures are ready in a few hundredths of a second and still follow each turn. Most of the wait after **Resume** on a very long session is the coding agent loading its conversation (#1147).
- **Transcript backups take about a third of the space, and can expire.** Once a session ends or is archived, Hive compresses its copy of the transcript in the project's `.hive` folder; you can still open, search, export and resume it as before, and backups from earlier sessions are compressed in the background. Storage now says what the backups hold before compression. A new setting, **Settings → Sessions → Keep transcript backups** (Always unless you change it), sends Hive's copies of sessions idle for 30 days to a year to the Recycle Bin, only for sessions the coding agent still has, so none becomes unreadable; a session whose only copy is Hive's is never removed this way (#1110).
- **The Workspace Overview opens at once, and usage totals no longer depend on transcripts.** Hive now records what each session used as it goes, in a usage history in the workspace's `.hive/usage.db`, read and written by a background thread, so the Overviews no longer read every transcript on Hive's main thread (on a workspace of 282 sessions and 565 MB of transcripts, the first open went from about 1.5 s to under 40 ms, and later ones from 75–140 ms to about 13 ms). A session's usage stays in the totals once you delete it or its transcripts are gone, a running session's is recorded about every minute, and card and lane costs come from the history too. The first time a workspace opens in this version, Hive imports what its existing sessions used in the background, losing nothing already counted; the Workspace Overview shows how far it is. `usage-cache.json` in your Hive profile is no longer used and is removed (#1106).
- **Polish: four more messages no longer guess a name's gender.** The note that a coding agent stayed busy while Hive switched its mode, the note above a provider's effort levels, and the "Hive closed unexpectedly" lines about a merge left half done made a past-tense verb agree with the agent's or provider's name. They now use the present tense or put "Agent" in front, as the rest of the Polish translation does (#1137).
- **Agents and the Assistant can tag cards without wiping their labels.** Changing a card's labels used to replace them all, so tagging fifty cards meant one change per card with each card's labels typed again, and a bulk change could wipe cards' other labels. The board tools and the Agent API now take `addLabels` and `removeLabels`, which add or take off only the labels named, in bulk too, and the card's history says just what was added or removed (#1131).
- **A long archive no longer slows the board down.** Hive read every card, archived ones included, for work it does many times a minute: checking for new decisions around each agent's board call, following lanes for their watches, ending reviews and archiving old Done cards. On a busy board that is mostly archived cards and their comments, so each check took about 65 ms and briefly held around 20 MB. These checks now read only the cards they need, in about 5–11 ms (#1107).
- **"Hive closed unexpectedly" knows about commands agents had only just started.** Hive keeps a record of what agents have started while it runs, so that after a crash its notice can list what is still running and offer **Stop Them**. A command an agent started just as its turn ended, or one started later by a process it left, could be missing from that record for up to a minute. Hive now updates the record a few seconds after anything new starts in an agent's session (#1134).
- **Cards say which doc sections to read first.** A card's new **Read first** lists sections of the project's docs or shared notes by file and heading (`docs/PLAN.md#setup`, `shared:plans/design.md#extraction-lanes`); each opens in Hive from the card, and the agent's start prompt lists them with their sizes, so it reads three sections rather than a whole build plan. Agents and the Assistant set them too. A reference that no longer resolves (its file gone, its heading renamed or now twice) shows on the card with the closest headings and is named in the agent's prompt, never silently dropped.
- **Agents read long documents by section.** Two new hive tools, **hive_doc_outline** and **hive_read_section**, give an agent a Markdown file's headings with each section's size, then just the section it needs, by heading or slug: for project docs and shared notes, so a 56 KB design note no longer fills an agent's context. The Agent API has them too (`/v1/docs/outline`, `/v1/docs/section`).
- **Put any agent in any pane.** Drag an agent's pane header onto an empty pane to move it there, or onto another agent's pane to swap them; panes can be left empty (*Drop an agent here*, with **Move Agent Here ▾** to bring in an agent from another page). From the keyboard, **Move Left/Right** and, in a grid, **Move Up/Down** (Ctrl+Alt+Shift+arrows) move the focused pane a cell, said to screen readers. Where you put them is kept for each layout and survives a restart, so switching layouts and back restores it; new agents take the first empty pane.
- **Less disk churn, and old files tidied.** Hive's settings file is written smaller and without a second copy at every save; the board's folds and the model lists now live beside it in `ui-state.json`. The backups kept when the board and other records moved into the workspace database go to the Recycle Bin two weeks after the move, Hive keeps only the newest three crash dumps, and its running marker is written without holding Hive up (#1111).
- **A lighter Progress panel.** While runs report progress, Hive now sends the window only the runs that changed, not every run it keeps up to four times a second, so a long Recent list no longer costs the window work on every step (#1108).
- **Fewer false "main process was busy" warnings, and real ones say what was running.** Time the PC spent asleep was counted as Hive being busy, so the log had warnings of many seconds while Hive sat idle. Hive no longer counts a pause that spans sleep, measures pauses more precisely, and each warning now names the window action, Agent API request or agent hook that was running, with how long it took (#1109).
- **Deleting the workspace folder no longer keeps Hive busy.** When the open workspace's folder was deleted or moved away, Windows kept telling Hive about it without end (about 99,000 notices in half a second), so Hive used a CPU core until it closed. Hive now stops watching the folder and looks for it again every few seconds, carrying on as before once it's back (#964).
- **A message left for an agent that's just starting on a task waits for that task.** An agent started with a task (a card's Start, a new conversation) is ready a moment before its coding agent takes the task. A message or wake that arrived just then could be typed first, so the agent read it before its task and Hive lost track of the line. Hive now waits until the task has been taken.
- **The Assistant hears your replies to agents at once.** When you answer an agent in its pane, the Assistant is told within seconds even when it isn't waiting on that agent at that moment (between its watches, or while it watches lanes), instead of a few turns later.
- **A stalled card says why when the agent's wake is stuck.** When an agent in a card loop watched its card but the wake Hive typed for it wasn't sent, the card now shows *"hasn't taken the wake Hive typed for #n: it waits in its prompt"*, with how to send it, instead of saying the agent ended its turn without watching.
- **Switching branch or pulling holds Hive's messages to that folder's agents.** While the Git view switches or pulls the project folder, the messages, wakes and tasks Hive sends agents working there, and agent starts there, wait until git is done, so no turn starts while files change under it.
- **Codex and Copilot agents take Hive's lines at the first Enter when busy.** A message's notice or a wake that reached a Codex or Copilot agent while it was busy for a moment could sit in its prompt until Hive pressed Enter again 10 seconds later, or, under heavy load, until you pressed it. Copilot now gets Hive's lines as a paste, as Claude Code does, and with Codex Hive presses Enter only once Codex shows the line.
- **The flight recorder catches rare events for you.** Some things happen too rarely to catch with the developer console open. Turn on a trigger in **Settings → Advanced** (all are off by default) and Hive saves the agent's recent developer console events by itself when it fires: a model's safeguards stopping a response, a CLI sending a field Hive doesn't know (often the first sign of a CLI update), an agent starting on a new CLI version, an agent gone silent mid-turn, or an event matching a pattern of your own. A capture is a redacted recording in Hive's `console-recordings` folder, with a notice and **Show in Folder**; the console's new **Captures** button lists them, and Copy Diagnostics offers the newest. Each trigger captures an agent at most once every 10 minutes, and Hive keeps the newest 20 captures. While a trigger is on, Hive keeps each agent's newest events in memory (redacted, at most 256 KB each); with all off, nothing changes (#698).
- **The developer console speaks your language.** Its window now loads Hive's language at all: it couldn't ask for it before, so it showed English everywhere (#1104).
- **The Performance view and the developer console are translated.** Both were English in every language; their headings, buttons, filters, explanations and notices now follow Hive's language, like the rest of the app. What the developer console records (events and recordings) stays English, as Hive's log does, so a recording reads the same to whoever it's sent to. The descriptions of the skills Hive ships are translated in the Skills view too, as the Assistant modes' already were; the skills themselves, which agents read, stay English (#1104).
- **Polish: "Aktywne" in the sidebar.** The Projects sidebar's section of active projects is now *Aktywne* in Polish, instead of *W pracy* (#1104).
- **No more garbled terminal text after long sessions.** Now and again, after hours of output, a line in an agent's terminal drew with letters from two drawings mixed (*Clicking the sow stili opegsathe agent*) until you scrolled. Terminals share a cache of drawn letters, and when it filled up and reorganised itself mid-drawing, letters already drawn in that moment pointed at the wrong place. Each terminal now redraws itself right after, so the text is right again at once (#1048).
- **No more endless "Compacting…" between turns.** When Claude Code prepares a compaction by itself while an agent is idle, it may never say it has finished; the agent then showed *Compacting the conversation…* until its next turn. It now shows ready again once the transcript shows the compaction, or after 10 minutes at most, as Hive's own Compact does (#1115).
- **Polish: Settings → Advanced's notes on a CLI no longer guess its gender.** The notes under a value that no longer matches what a CLI sent or showed made their verbs masculine to agree with the CLI's name; they are now worded without agreement, like their sibling note (#1132).
- **The code editor's right-click menu is readable again.** In the Files tab, the editor's menu (Go to Symbol, Format Document, Cut, Copy, Paste…) showed dark text with no background or border. It now looks like Hive's other menus in both themes: a surface with a border, readable entries and shortcuts, and the hovered entry filled with the accent colour (#1102).
- **An agent that stops its own background task no longer shows Working afterwards.** When a Claude Code agent stopped a background command itself (`TaskStop`) just before its turn ended, Hive took the task's end for one that wakes the agent and showed it working with no turn running, refusing tasks given to it, until Claude Code's idle notice a minute later. It is now finished at once (#640).

- **Session records join the board in its database.** Each project's `.hive/sessions.json`, rewritten whole at every change of a session (746 KB on a busy project, about 7 ms a time), is now rows of the workspace's `.hive/hive.db`: a change writes only the record it changes, in well under a millisecond, with no temp file or rename for Windows to refuse. The file moves in the first time Hive reads a project's sessions and is kept as `sessions.json.imported-<date>`. **Remove from Hive** writes a project's sessions back into its folder, so restoring it, or opening it in another workspace, brings them back; a folder copied or moved by hand starts with an empty list, as its cards do (#1061).
- **Agents and terminals find the Claude Code Hive found.** When Claude Code's own installer left its folder off your PATH, Agent Setup found Claude Code but a shell Hive started couldn't run `claude`. Hive now adds the folder of each CLI it finds to the PATH of what it starts, without changing your own PATH (#1103).
- **A warning for Codex with the Store's PowerShell 7.** Codex's Windows sandbox can't start the Microsoft Store's PowerShell 7 while another copy of it is open, so Codex agents' commands failed at random. Agent Setup now warns when that PowerShell is the one Codex would use, says how it shows, and how to switch to the installer's PowerShell 7 (#585).
- **Copilot compactions show up.** A Copilot agent's compactions now count in its usage and appear in the Sessions tab with their summary, and after a `/compact` typed in its terminal the agent shows as ready again once Copilot has finished, not only at your next message (#454).
- **Plan usage no longer flips between figures.** With several agents running, the status bar's weekly figure could jump back and forth (98%, then 96%, then 98%) because each session passes on the figures from its own latest request, and a resumed Codex session could even bring back last week's. Hive now keeps the highest figure each limit has reached in its reset period, takes the new one as soon as it resets, and its tooltip says which agent reported each limit (#383).
- **The Assistant's start view on Codex and Copilot.** An Assistant running on Codex or Copilot now gets the same short view of where things stand as on Claude Code: each time it starts, and again after its conversation is compacted (on Copilot, with your next message after a compaction) (#1065).
- **Card loops review committed work.** The card-loop skill now has the builder commit each round before sending a card to Review and name the commit; a reviewer handed uncommitted work asks for a commit rather than failing the round over it (#1074).
- **The Assistant steps in when a review keeps finding new edge cases.** When a lane's card fails review a second or third time on the same kind of finding, the Assistant brings you a simpler option with its recommendation instead of letting the loop run on. For a push or a release, it asks you to give your OK in the agent's own pane, since the agent's CLI refuses an OK passed on by the Assistant (#1075).
- **The Assistant puts your decisions on the card.** When you decide something about a card in the Assistant's pane, it records the decision on the card first, where the card's agent sees it, and its journal only notes it. An agent's question it brings you is passed on in the agent's own words (#1136).
- **QA triager mode files better cards.** A new Assistant skill, **triage-report**, has the QA triager find the cause in the code before it writes the card, check for a card that already covers the problem (including ones reviewed but not merged yet), and file the card with what you saw, the evidence and how to tell it's fixed (#408).
- **The Assistant tidies the board.** Ask it to tidy the board, and a new skill, **board-hygiene**, has it link duplicate cards for you to archive, record your answers as decisions on their cards, and raise blocked reasons that are out of date (#409).
- **A licence audit skill for agents.** **licence-audit** has an agent check the licences of everything a project ships (dependencies, bundled libraries, files vendored inside packages, fonts and icons, what the installer adds), report them in a table and flag anything that isn't plainly permissive for you to decide (#410).

## 0.9.2 — 2026-10-19

- **Retry a Copilot update that WinGet refuses.** If WinGet cannot remove the old portable package, Agent Setup explains that its files may have changed (for example, through Copilot's own updater) and offers **Update anyway** to retry with `--force`. Hive only forces the update when you click it, and still asks you to stop running Copilot agents first (#1101).

## 0.9.1 — 18 October 2026

- **MCP servers: a workspace switch and each project's own choice.** A server now runs in a project only when it's on in the workspace and on in that project. Adding a server adds it turned off, with no questions. Turning its switch on in the MCP view shows what it runs and asks which projects to turn it on in (the selected project ticked); turning it off stops it everywhere and keeps each project's choice for next time. New projects start with servers off, and a project's MCP tab says **Off in the workspace** where its switch is waiting on the workspace. Upgrading changes nothing that runs: servers on for all projects stay on wherever they were.

- **Start small, finish a block, start fresh.** The user guide's Getting started now says how to keep a plan's usage down: one agent to begin with, a lighter model for routine work on project agents (not the Assistant), work in blocks of a few hours, then start every session fresh. The Assistant suggests it once, in a line, when every lane has ended or an agent's card is done with nothing else running, and checks its journal holds what is still open before it does.
- **The Assistant's start view stays short on a big board.** What waits on you now shows at most ten lines; past that, agents asking now and cards blocked on a question first, then On Hold cards waiting on a decision of yours, before those waiting for a later version, then a count of the rest. The other sections are capped too, so a board with sixty On Hold cards no longer adds thousands of tokens to every new Assistant conversation (#1078).

## 0.9.0 — 18 October 2026

- **The Assistant keeps a journal.** Each workspace's Assistant has a journal, its memory across sessions: decisions, plans, events, incidents and what it learned, each a line with optional detail and links to cards and commits, searchable and recalled a few lines at a time instead of a long handover. Hive adds facts as they happen (lanes started and ended, merges, cards into Done, an unexpected close). **Settings → Assistant → Journal** turns it off (keeping it), chooses what it may store (work only by default), how long everyday entries stay (90 days) and a size cap (50 MB), and deletes it. It is kept on this computer only, in `.hive/assistant/journal.db` (#1031).
- **The Assistant picks up where it left off.** With its journal on, the Assistant gets a short view of where things stand each time it starts and after every compaction: what waits on you, the cards in hand, lanes and agents, and the few journal entries that matter now, kept to about two thousand tokens. It writes your decisions in your words as you make them, recalls before deciding from memory, and writes a weekly digest. Asked for a handover, it says one isn't needed and writes one only if you still want it; with the journal off it writes handovers as before and suggests the journal once (#1032).
- **A long conversation's notice no longer offers to cut into an agent's work.** When an agent's transcript passes *Warn when a transcript is over*, the notice says so, and offers **Hand Over to…** only while the agent is idle, not merging and not on a card loop's card; otherwise it says the agent can hand over when it has finished. Hive checks again when you click, and just before the conversation ends: an agent that took the merge slot or started other work while it wrote its handover keeps its conversation (#1057).
- **Read and correct what the Assistant remembers.** The Assistant view has a **Journal**: its journal as a timeline, newest first, with the cards each entry links to. Search it and filter it by kind, project, who wrote it and dates; open an entry for its detail and why, edit or delete it; **Forget These…** deletes everything a search finds, after saying how many. The weekly digests have their own list, the footer shows the size and retention, and while the journal is off it says so and stays readable (#1033).
- **Panes give way on a narrow window.** When the panes of your layout would be too narrow for a terminal (the narrowest window with the sidebar and the Progress panel open, say), the Session tab shows fewer columns for now (two columns become one at a time, three become two) instead of terminals cut off at the pane's edge. Your layout isn't changed: its button still shows it, and the panes go back to it once there is room. In Tiles' focus view, the agent's terminal comes first: the strip of agents takes at most two fifths of the width, narrowing to its least before the terminal narrows, then steps aside to keep the terminal whole.
- **Dismiss a "has finished" row in the Assistant panel without going there.** Pointing at (or tabbing to) a row in the panel's Workspace section now says what a click does (*Click to open HR3 and dismiss*), and a finished agent's row has a small **×** on its right that removes it without opening the agent. It comes back only when that agent finishes again.
- **Fewer project tabs, numbered in order.** **Memory**, **Skills**, **Templates** and **MCP** have moved into a **More ▾** menu at the end of the project's tabs, which shows the name of the one that's open. The tabs left are numbered as they appear: **Alt+1** Session, **Alt+2** Overview, **Alt+3** Performance, **Alt+4** Tasks, **Alt+5** Sessions, **Alt+6** Files, **Alt+7** Attachments and **Alt+8** Git (Alt+0 is still Project Settings), and the menu bar's **Project** menu lists them the same way. **Changed shortcuts:** Sessions was Alt+3, Files Alt+4, Attachments Alt+5 and Git Alt+6; Memory (Alt+7), Skills (Alt+8) and MCP (Alt+9) have none now, but are in the Project menu and the command palette, and you can give them one in **Settings → Keyboard Shortcuts**. Shortcuts you set yourself are kept.
- **The task board is kept in a database.** A workspace's cards move from a thousand small files in `.hive/tasks` into one SQLite file, `.hive/hive.db`, the first time 0.9 opens it (the old folder is kept as `.hive/tasks.imported-<date>`). Every change is saved whole or not at all, and the renames that Windows could refuse while another program held a card file are gone: archiving 170 cards with 12 agents running takes under a tenth of a second. The board sends archived cards to the window in short until you open **Archived** or one of them. **Export Board to JSON…** (the board's **⋯** menu) saves the cards as files again. (#1017).
- **Performance metrics join the board in its database.** Hive's performance metrics were one `.hive/metrics/metrics.json` rewritten whole, up to 2 MB, every 30 seconds while you worked; they are now rows of `.hive/hive.db`, one per hour or day, so a save writes the hour under way and adds each new one. The file moves in the first time 0.9 opens the workspace, with the same numbers on **Performance** and **Overview**, and is kept as `metrics.json.imported-<date>` (#1019).
- **Lanes, card watches and agents' inboxes join the board in its database.** The card loops' lanes (`lanes.json`), agents' card and agent watches (`watches.json`) and each project's deliveries, what Hive has for its agents to read (`deliveries.json`, the busiest of them, rewritten whole at every message), are now rows of `.hive/hive.db`: each change writes only what changed, in one transaction, with no temp file or rename for Windows to refuse, and a watch can no longer be saved after its workspace closed. Their files move in the first time 0.9 opens the workspace and are kept as `….imported-<date>` (#1018).
- **Review cards made by an older Hive.** An older Hive shows an empty board for a workspace whose board moved to the database; cards added there are set aside in `.hive/tasks.set-aside` when 0.9 opens it again. **Review…** on the notice (or **Set-Aside Cards…** in the board's **⋯** menu) lists them, and **Add to Board** adds each one, under its old number when it's free, or **Discard…** sends it to the Recycle Bin (#1044).
- **Backing up a transcript no longer gets in the agent's way.** Hive's first copy of a session's transcript could stop its coding agent writing to it at that moment (Windows reported the file busy): Hive now reads the transcript in a way that lets the agent keep writing. It was seen once in Hive's tests, where it ended an agent's session at its first prompt (#1041).
- **The window title no longer runs into the menu.** In a narrow window in a language with long menu names (German's "Hilfe" ran into the project's name), the title now moves aside and is shortened with "…", or hides when there is no room.
- **Switch Now doesn't wait on one agent.** When you change the permission mode setting with agents running, **Switch Now** switches them side by side: one Codex agent waiting for your answer to its Full access warning no longer holds up the others (#1024).
- **A test run left over from an ended session says so.** A test run waiting for its turn now names a run holding the slot whose agent's session has ended as *left over from a session that ended*, and a run starting in the same worktree says so, so a resumed agent knows its earlier run still goes; nothing is stopped on its own. The Agent API says whether an agent's launch still runs (`GET /v1/projects/{name}/agents/{agent}/launches/{run}`).
- **Codex switches to Full access without a restart.** Choosing Full access for a running Codex agent now switches it in place after Hive's confirmation, through Codex's own `/permissions` menu like the other presets; answer Codex's own warning in its terminal and the conversation carries on. Claude Code's Bypass permissions still restarts the session when Claude Code requires it, and the mode menu says *Restarts the session* only under modes that will.
- **Fewer leftover files in `.hive`.** A save that fails now always removes its temp file, and opening a workspace removes what earlier failed or interrupted saves left there (temp files over a day old) and the copies the project-id migration made of each card before changing it (`*.before-ids.bak`, over a week old), saying in Hive's log what went (#1016).
- **Tiles: your whole team on one screen.** Switch the Session tab to **Tiles** and each agent becomes a small tile: its state, name and provider, its status, its card, its progress and the first two lines of its latest reply, with badges for background tasks and warnings. Twelve fit a page, and agents waiting for you stand out. Click a tile (or press Enter) to open the agent's pane large, with the others in a strip beside it, each with a small chip after its name giving its card's number, tinted with the board column the card is in (Doing, Review, Passed, or red when blocked): click it to open the card. Long names end in an ellipsis before the chip. Drag the strip's edge to widen or narrow it (double-click resets it; the width is remembered); **Esc** outside the terminal, or **Ctrl+Alt+Esc** from anywhere, goes back. **Settings → Sessions → Tile order** keeps the panes' order (the default, with a count on the page buttons of agents waiting elsewhere) or puts the agents that need you first. The tiles show what Hive already knows: no terminal is drawn for them and no CLI is asked anything. In the panes' order, drag a tile onto another to swap them, or onto a page button to move it to that page (**Move Left** / **Move Right** in a tile's menu, or Ctrl+Alt+Shift+Left / Right, from the keyboard); the panes follow.
- **When Hive closed unexpectedly, the next start says so.** If Hive was ended without quitting (a crash, something ending its process, the power), the next start shows when it was last seen, which agents were running in which projects, whether a crash dump was kept and any merge left half done, with the folder to check. **Resume All** resumes those agents; nothing resumes on its own unless you turn on **Settings → Sessions → Resume agents after an unexpected close**. It also lists what the agents had started that is still running (test runs, servers), from Hive's own record of their processes, with **Stop Them** to end exactly those; nothing is stopped on its own. A command an agent ran through `hive-progress` (a test run, usually) is one item named by its title, and Stop Them ends the whole run. A process of the run that Windows lets Hive neither end nor check is never counted as stopped: each press of Stop Them after says it may still run, with its process ID to look for in Task Manager, since Hive can no longer tell it from another process. - **Hive no longer runs out of memory when many cards change at once while agents are running.** Each card saved told the board twice, and for each time Hive read the whole board again once for every running agent, never waiting for the last read to finish: archiving 76 cards with agents running took over a minute and could close Hive (its main process ran out of memory). - **Knowing why Hive stopped.** Hive now keeps a crash dump when it, its window or one of its helper processes crashes, in `%APPDATA%\Hive\Crashpad\reports` on your PC only: it never sends one. Help → Copy Diagnostics names the newest, for you to attach to an issue. Hive's log also says how every run ends (a quit and who asked for it, an update, Windows shutting down, sleep, a crash of its window or an error nothing caught), so a run whose log just stops was ended from outside.
- **A calmer project header and tabs.** The project header is one quiet row: the project's name, its agents' states in one line, counting the idle and stopped ones too (*1 waiting · 2 working · 7 idle · 2 stopped*), the **Active** switch, **Resume** and **Stop**, and an **Agents ▾** menu for **Start New**, **Archive and Start New** and **Remove All…**, which were three buttons. **Resume** and **Stop** are quiet buttons like **Agents ▾**, their colour on the icon (Stop turns red as you point at it), with short labels, **Resume (2)** and **Stop (10)**, whose tooltips say them in full. The header is a few pixels shorter, closer to the tabs, and the project tabs are shorter and tighter, and **Project Settings** has left them: it opens from the header's **⋯**, **Project → Go to Project Settings** or **Alt+0**.

On a narrow window the toolbar folds: **+ Add** becomes just **+**, then **Panes | Tiles** become icons (point at one for its name), and the agents' counts are shortened last.
- **Agent states you can tell apart without colour.** Hive sums up each agent as waiting for you, stalled, working or idle, each drawn with its own shape (a diamond, a square, a pulsing dot, a ring) as well as its own colour; the project header's state line uses them first.
- **A quieter pane header.** Each agent's pane header now shows only its state, its name, its status and its card, with **Stop** (or **Resume** while it isn't running) and **⋯**. Everything else is in **⋯**, also a right-click on the header: Compact…, Hand Over to…, Review Changes and Merge… (with what is left to merge), the agent's settings and Remove. Hover the agent's name for its provider.

In a narrow pane the size goes first. The running session's name, Open in Sessions Tab and Rename Session… are in the agent's ⋯.

- **A session's automatic name is the same everywhere.** Until it has a name, a session is named by when it started. The agent's footer and the Sessions tab could show that time a minute apart, and a resumed session's footer showed when it was resumed. Both now show when the session began.
- **What agents left running survives a restart.** Processes an agent left running that Hive didn't ask you about as it quit (a quit to install an update, or with no window open), or that were listed when it crashed, are listed again the next time Hive starts, with **End Them** and **Keep Running**. Hive checks that each is still the same process, so it never offers to end a program that has since taken its place. A dev copy of Hive that an agent's test run left open now shows up there too.
- **Agents stop what they start.** Agents watching their own test runs with `tail -f` left those watchers running long after the runs ended (16 from one agent in a day). Hive's guidance now tells agents to watch a run with something that ends with it (`hive-progress`, their CLI's notice that a background command ended) and to end the watchers, servers and app copies they started before a card goes to Review.
- **Stopping a run ends only what it started.** When a command run with `hive-progress` is stopped, Hive ends it with what it started, as before, but now checks when each process started: a process that only shares a parent id the command happens to have reused (an older one whose parent had ended) is left running.
- **An idle agent no longer stays "Working…".** When Hive missed how a Claude Code agent's turn ended, the agent could show **Working…** at an empty prompt for good, and the Hive Assistant couldn't give it a task. Hive now takes Claude Code's own "waiting for your input" signal, a minute after a turn, and shows the agent idle again. Claude Code's compaction while idle and its recaps leave an idle agent idle.
- **An agent's status follows its CLI's turns, so it can't freeze.** Hive now tracks each turn by the CLI's own id. A tool result that reaches Hive after its turn has ended no longer puts a finished agent back to **Working…**, and a turn whose end Hive never heard of is closed from the CLI's own record (Codex's log of the finished turn) or from its idle prompt on screen (Claude Code 2.1.296 and Codex 0.162.1). When there's no sign either way, the agent shows **Silent 23 min · state unknown** instead of pretending to work or to be idle: nothing is typed into it, and **Mark idle** in its pane puts it right. Each hook Hive receives is now logged, with its ids, in `hooks.log` beside `hive.log`, so a stuck status can be traced. A card loop's stall line now says what the reviewer is really doing, not just that it's watching.

### MCP servers
- **Give a server to some agents only.** An agent's settings now have **MCP servers: All of the project's / Only these**, so a server's tools reach only the agents that need it (a release-testing agent gets a sandbox server, the builders don't) and the others keep a smaller context. All of the project's stays the default; Hive's own `hive` server is always given; templates keep the choice. ### Git
- **Initialise repository, in one click.** A project that isn't a git repository has an **Initialise repository…** button on its Git tab: it makes the folder a repository on a branch called main, keeps its .hive out of git before anything is staged, adds a starter .gitignore if you choose one (minimal, Node, Python, .NET or Godot; a .gitignore of the project's own is kept), and makes the first commit, so agents can work in worktrees at once. With no name or email set in git, it asks for them and saves them to that repository only, never your global config. A folder inside another repository needs your confirmation, and one another version control system keeps is refused.
- **The Git view.** A project's **Changes** tab is now **Git**, with three sections: **Changes** (as before), **History** (the last 20 commits and the tags) and **Branches & remotes** (the branch, or a detached HEAD or a merge or rebase in progress; the remotes and their URLs; the branch it tracks and how far ahead and behind it is; the other worktrees; and who commits are made as, this repository's and your global identity, with a warning when commits would fail or would show a personal email on GitHub). From there you can switch or create a branch, fetch, pull, push, tag, add a remote or change its URL, and set this repository's identity: these are yours alone, never an agent's. ### Advanced settings
- **Fix a CLI change without waiting for Hive.** **Settings → Advanced** now lists the details Hive relies on that a coding agent's update can break (each CLI's folder trust question, the text that means it's ready, the messages that mean its sign-in was refused, the fields Claude Code and Codex send plan limits in, Codex's title items) and timeouts for power users (each CLI's hook timeouts, the `hive` tools' reply timeout and Codex's timeout for them, the longest card and agent waits), plus how many lanes the Progress panel shows, which a workspace can set for itself. ### Files
- **A late paste no longer takes your selection.** In the Files tab, a paste, rename or new file that took a moment (a big folder, a slow disk) selected what it made when it finished, even if you had clicked another row meanwhile, so Ctrl+X or Ctrl+C then acted on the wrong file. The row you clicked now keeps the selection.
- **Deleting something open for a moment.** Delete Project, and every other delete to the Recycle Bin, failed at once when Windows couldn't move the item because something had a file in it open, even for an instant (an antivirus scan, the search indexer). Hive now tries again for about a second and a half, so only a program that keeps it open stops it, and Hive still says so.

### Agent API
- **Agents can read the developer console.** **Settings → Agent API → Let agents read the developer console** gives agents and the Hive Assistant a read-only tool, `hive_console`, showing what their CLI sends Hive (hooks, status line, transcript records, the terminal signs Hive reacts to) next to what Hive made of each. An agent reads only its own sessions; the Assistant reads its workspace's agents and Hive's own events (API calls, merge slots, watches, Progress). An agent's state on the stream now says *that* a message waits for it or it asked something, not what.

### Lanes and loops
- **Card reports lead with a one-line summary.** Round reports and review verdicts start with one line (*"Round 2 ready: …"*, *"Round 1: FAILED: 2 findings: …"*) and the detail follows, and agents and the Assistant can read just those lines of a card's comments, so following a loop no longer means reading every long report in full.
- **The Assistant watches whole lanes.** Instead of a list of at most 20 cards it swapped in and out (and once missed a card waiting for review), the Assistant waits on every running lane at once, lanes started later included, and is woken only for what needs it: a failed review, a blocked or stalled card, a lane ready to merge, a lane ended. Routine moves no longer wake it.
- **The Assistant can leave a message for a busy agent.** Agents in a card loop are nearly always waiting or working, so the Assistant couldn't pass on your answers or re-brief them, and you pasted its messages into their panes yourself. Now it leaves the agent a message: one waiting on its cards gets it at once and keeps waiting afterwards, and a busy one gets it as soon as its turn ends. The agent's pane shows **✉ 1 message waiting** until then; hover to read it, click to cancel it.
- **Your card loop defaults are settings.** **Settings → Workspace → Card loop rounds** and **Card loop wait** set how many rounds a card gets and how long agents wait before telling you, for every loop in the workspace that doesn't say otherwise; a project can set its own in its **Settings → Card loops**. They start at 10 rounds and 6 hours (they were 5 and 2 hours), and what you say when you start a loop still wins.
- **Hive wakes reviewers and builders itself.** When a card arrives in Review, Hive wakes its reviewer; when the review gives its verdict, Hive wakes the card's builder, even when that agent didn't set a wait, so a loop no longer stalls because one agent forgot. It only does this for cards with a reviewer (the reviewer of the card's lane, or the agent that last reviewed it), only while the agent is idle, and never when the agent's own wait already tells it. The card's history says whom Hive woke. Turn it off for a project in its **Settings → Card loops**.
- **Hive knows the card loops it runs.** When two agents work through cards as builder and reviewer, the loop is kept as a **lane**: its builder and reviewer, its cards in order, its rounds and its wait. The builder registers it as it starts and the reviewer joins it, with nothing for you to set up. Hive follows the board from there: the lane is on the first card not yet passed, **paused** while that card is blocked, and **ended** once its cards are all Done. A lane whose builder or reviewer you remove is **abandoned**. The Assistant can list the lanes and start one when it briefs a pair, and scripts read them through the Agent API (`/v1/lanes`). A lane is only a record: an agent working on a card on its own has none, and a loop works the same without one.
- **Agents write tests that hold up on any machine.** The bundled work-on-card and review-agent-work skills now say that tests wait for what they expect to see, never for a length of time: no sleeping and then checking, no single read just after an action, no raised timeout as a fix, no test depending on another's leftovers. Reviewers fail a new or changed test that does, since it fails on a loaded or slower machine.
- **Reviewers don't repeat the builder's test runs.** In a card loop the builder's run record (which checks ran, on exactly which code) is what the reviewer checks, rather than running everything again: the bundled review-agent-work skill now has it run the quick checks, the tests the change affects and its own probes of the riskiest parts, and a whole suite again only when the record is missing, for other code or doubtful, or the change is to shared test code, saying why. Reviews take less time and fewer tokens, and don't load the machine while other agents test.
- **The Assistant runs a team out of the box.** In Coordinator mode, a new skill that comes with Hive, `run-lanes`, has the Assistant plan lanes by the files each touches, brief every builder and reviewer in full, and watch each lane to its end, checking the board whenever a lane changes and what agents report, instead of leaving lanes to "tell you". It does this when a project has a team (three or more agents, builder and reviewer pairs, or agents in worktrees); with one or two agents it stays light and at most suggests more structure in a line, and you can still use card loops and everything else. If it starts a lane without watching it, Hive's reply reminds it, and when a card wakes it while lanes are running, Hive reminds it to watch them all again.

### Fixes
- **Sizes and token counts read cleanly.** The Performance view showed an average under 1 KB unrounded ("160.17241379310346 B") and billions of tokens in millions ("12904M"). Sizes are now whole bytes ("160 B") and token counts have a billions unit ("12.9B"), everywhere Hive shows them; a value that would read "1000k" or "1024 KB" shows in the next unit ("1.0M", "1.0 MB").
- **Wakes are sent when Claude Code is busy for a moment.** About one wake line in fifty sat in an agent's or the Assistant's prompt unsent, even after Hive pressed Enter again, until you pressed Enter yourself. Claude Code, busy for a moment, read Hive's line together with the keys around it as a paste and kept those keys as text. Hive now puts its lines into Claude Code as a paste, which Claude Code reads as text however it arrives. A long line shows as *[Pasted text #1]* in the prompt until it is sent.
- **Board changes stay quick on a big board.** Each new card, move or batch change read every card file, one at a time, while other changes waited: on a board of 500 cards, a new card took about 0.2 s and a batch of 30 changes over 5 s. Placing a card now reads only the cards changed since, and the board is read several files at a time: about 0.1 s and 2 s.
- **A reviewer waiting for a card that came back to Review is woken.** A reviewer told a card was in Review, which then went back to Doing (blocked to ask you, say), and asked again to wait for it to be in Review, was never woken when it came back: on 10 Oct three reviewers sat waiting for five hours on cards already in Review. Hive now wakes them. A card that waits in Review for 15 minutes while its reviewer waits for it, without its review starting, now shows as **stalled** on the board and in its lane's row in the Progress panel, and an agent whose turn ended while its background tasks run (a long test run) is no longer reported as not watching its card.

Settings left to the defaults say so in a muted *(default)*, and a new worktree shows its branch, with its folder on hover. Before, each agent was a long line that wrapped mid-path, which was hard to read for a template of 12 agents.
- **Save in a template's agent saves the template.** Editing a template, then pressing **Save** in one of its agents' settings, changed nothing until you also pressed **Save Template**, so the change was easy to lose. The agent's Save now saves the template, and the editor stays open. Other changes not saved yet are marked in the editor and in the list, and are kept if you go to another template and come back. Quitting or reloading asks about them, as it does for unsaved files.

Repair moved the project but not its cards. Hive now names a project by an id kept in its own `.hive` folder, so cards, lanes and agents' watches follow a rename or a move, even one made while Hive runs, and watches also follow a move of the whole workspace. A merge left half done when Hive closed is reported in the project as it is now. A renamed project also keeps its handovers (so an agent picking up finds the latest one), its Performance history and kept comparisons, its Progress runs and its tabs' view settings. They also stay with their own project when two projects swap names or a new folder takes the old name. Cards saved before this version still name the old folder: for a project renamed since, the banner offers **Repair…**, which gives them to the project they belong to now. That is the project renamed from that name, or else the one whose agents worked on them.

The settings and runs then followed a folder that no longer existed. The retry now uses the folder names as they are now.

- **A blocked card in a loop is reviewed when it comes back.** When a builder blocked its card to ask you a question, its reviewer dropped the card and moved on to the next one, so once you'd answered and the card was back in Review, nobody reviewed it and the loop stalled. Hive now warns when a project or worktree has a `.codex` folder holding something other than Codex's configuration (its config, custom agents, rules), and agents are told to keep scratch, probes and logs in a temp folder, out of projects and their `.codex`, `.claude` and `.agents` folders.

Hive now compares these by where the folders really are.

- **See which Claude Code and Codex versions Hive was tested with.** Each release now records the CLI versions its tests ran against. **Help → Agent Setup** shows them next to the versions you have (**Tested with 2.1.287 · installed 2.1.290**), with a calm note when yours is newer or older, and **Copy Diagnostics** includes them for bug reports.
- **Hive's hook keys stay out of your projects.** The key Claude Code's and Codex's hooks use to report an agent's status to Hive was written into each project's `.hive` launch settings (and into Codex's command line), where a commit, a sync service or a zip could carry it. Hooks now read it from a file in Hive's own data folder, each session has its own key, and a key stops working when its session ends. Each Claude Code session's settings and MCP server configuration, which can carry your MCP servers' keys or a `--settings` file's `env`, moved there too, out of the project.
- **Hive tells you when a project's `.hive` isn't kept out of version control.** Hive adds `.hive` to git's exclude file by itself, now also for a repository made later (`git init`) or one in a folder above the project, and asks git whether it really ignores it. Where it can't (no git, another version control system, a OneDrive or Dropbox folder), the project's Overview and Project Settings say so, with **Exclude** where Hive can fix it.
- **Hive tells you when a sign-in expires.** When Claude Code's or Codex's sign-in expired, its agents' turns stopped but Hive kept showing them as working, so card loops sat stuck until someone noticed. Those agents now show **Needs sign-in** (a violet dot), you're told once for the CLI however many agents stopped, and the tooltip says how to sign in again. Once you have, **Resume All Agents** in the project header carries on the agents that didn't carry on by themselves. A Claude Code turn that ends on another API error (a rate limit, say) now ends as finished too, instead of staying working.
- **A `--settings` in Claude Code's extra arguments no longer switches off Hive's hooks.** Claude Code reads only one `--settings`, so adding your own replaced the one Hive starts it with: the agent's status, file locks and status line (context, cost, plan limits) stopped working. Hive now merges your settings into its own, so both apply. A `--settings` with no value, or settings that are missing, aren't a file of at most 2 MiB, aren't JSON, or would turn off Hive's hooks (`disableAllHooks`), stop the agent from starting, with a message saying which.
- **The context tooltip says where Claude Code compacts by itself, and why.** "Compacts by itself at about 167,000" is marked as Claude Code's default for the window, and when its settings change it (an auto-compact window in its settings or for one model, `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, also in a settings file's `env` block, an earlier percentage, or a `--settings` file or JSON in an agent's extra arguments) the tooltip gives that figure and names the setting, or says auto-compaction is off. Hive only reads those settings, when the session starts, and only the files Claude Code reads (`--setting-sources`, `--restricted`, its 2 MiB limit). A default is called an estimate, since managed policies Hive can't read could change it, and so is any answer when Hive couldn't read a settings file or can't tell which ones Claude Code reads.
- **Codex's sandbox setup brings up its prompt on a busy computer too.** Agent Setup's **Set up** for the Codex sandbox could type into Codex while it was still loading, so Codex queued the keys and its setup prompt never appeared. Hive now waits until Codex has loaded.
- **Restart session restarts on a busy computer too.** Clicking **Restart session** (after changing an agent's effort, skills or settings) could, on a busy computer, ask whether to stop a session that had already stopped (*…already has a running session*) instead of restarting it. It now restarts straight away.
- **A Codex approval prompt is told once.** On a busy computer, Hive could tell you twice that a Codex agent needed your input for the same approval prompt (the first one in a new session). It's told once now.
- **Footers show the model that actually runs.** An agent or the Assistant set to **Opus** now reads *Opus 5.5*, like an agent on the default (*Opus 5.5 (default)*): the running session's own model, else the model the alias stands for, with *chosen as Opus* in the tooltip. The model pickers list aliases with their model, *Opus (Opus 5.5)*, as Claude Code reports them.
- **New models show up without waiting for a Hive update.** Hive now asks Claude Code and Codex which models they have and what each can do, for your installed version and your account (no tokens, no session), so the model pickers list exactly what the CLI reports: Fable, GPT-6.1 Sol, or whatever your plan adds next. **Effort pickers offer only the chosen model's levels** (Haiku has none, Opus 4.6 stops at Max, GPT-5.5 at Extra high); an effort a model doesn't take stays chosen and is marked, never changed for you. With no effort chosen, the agent's footer shows the model's own default, e.g. *Medium (default)*. The Auto warning for Haiku now comes from what Claude Code says.
- **Every fallback is yours to edit.** When a CLI can't be asked, **Settings → <provider> → Models (fallback)** and **Effort levels (fallback)** are used, and you can add, remove and rename entries, with **Reset to defaults**. The **API prices** table now takes new models and removals too, with **Reset to defaults**, and says when Hive's prices were checked.

### Task board
- **Decisions on cards.** What you decide about a card now has its own place: **Decisions**, pinned above the comments in the card, each saying who wrote it down and marked **new since start** when it came after work began. You, the Assistant or an agent you tell can record one (it is always your decision); only you change or remove one. - **Archive a whole column, or the whole board, and undo it.** Each column's **⋯** has **Archive All in Done (23)…**, and the board's **⋯** **Archive All Cards…**, counted per column. - **Two agents can build and review a list of cards in turn**, without you passing each card between them: tell one *"work through #111 to #117 as the builder"* and another to review them. Each waits for the other without running, and Hive wakes it with a line when the card changes. The waiting agent shows **Waiting for #112 → Review** in its header, with **Cancel**. The wake line names the reviewer of a verdict (*"#112 is in Review: Codex (hive) failed it"*), and on another agent's card, one an agent's own work depends on, whose card it is and that Passed isn't merged yet (*"#111 (Claude's card) is in Passed: Codex (hive) passed it (Passed isn't merged)"*); Done means merged. New `card-loop` skill.

- **Move an open card out of the way.** Drag a card's dialog by its header to see what's behind it; it stays within the window, and opens in the usual place next time.
- **A project's Overview shows its cards at a glance**, as the Workspace Overview does for the whole board: how many of the project's cards are in Todo, Doing, Waiting for review and Done, and how many are stalled or blocked, updated as cards change. Click a number to open the project's Tasks tab.
- **An agent can't finish another agent's work in progress.** A card in Doing with one agent can't be moved to Review or Done by another agent (for example a reviewer whose review ended because the card went back for more work); Hive refuses it and leaves the card as it was. The card's own agent, you, the Assistant and scripts with the workspace token still can.
- **Agents review cards without taking them.** Ask an agent to review a card and it stays in **Review** with the agent that did the work, showing **Reviewing: Codex** on the board and an eye on the reviewer's tab, until the reviewer gives its verdict as a comment. Before, a reviewing agent moved the card to Doing, so the board showed the agent that did the work as busy on it. One agent reviews a card at a time, the review ends by itself if the reviewer stops or the card moves, and the Sessions tab says which cards a session reviewed.
- **Agents keep to their own project's cards.** An agent can see and change only its project's cards on the board: another project's cards are for that project's agents, the Assistant and you. Before, an agent in one project could list, read, comment on and move any card in the workspace. An agent also can't read or type into another project's agents' conversations any more, where those cards appear as their tasks. Each agent now calls Hive with a token of its own, so it can't get round this by saying it is someone else. The Assistant and your board still see everything.

- **Agents move a card to Doing when they start on it.** Hand an agent a card in its conversation (*"task #59 please"*) and it moves the card to Doing before it starts, then to Review when it's done. The agent's prompt says the card is back for more work. An agent picking up a card in its conversation does the same.

### Skills and agent guidance
- **A warning over Hive's skills.** The Skills view, and a Hive skill while you edit it, say that editing these skills may change how agents behave in Hive.
- **Hive keeps its skills up to date in your workspaces.** When a new version of Hive improves one of its skills, a copy you haven't changed is updated when the workspace opens, and skills new in that version are added. Before, only a new workspace got them, and existing ones had to **Revert** each by hand. A skill you edited stays as you wrote it: its page says **Update available** when Hive has a newer version, and **Revert to default** takes it. A skill you deleted stays deleted. Hive's personas are kept up to date the same way.
- **New skills: `work-on-card`, `coordinate-agents` and `use-hive-api`.** Agents carry a card from Doing to Review with `work-on-card`. The Hive Assistant runs agents and cards with `coordinate-agents`, its first skill (before, the Assistant got none). `use-hive-api` helps an agent write scripts against Hive's Agent API. `review-agent-work`, `pick-up`, `handover`, `merge-ready`, `split-work` and `workspace-note` are clearer about when they apply and what they check. For example, a review covers what changed since the last one, and a pick-up doesn't stop to ask when you've said to carry on.
- **Leaner instructions.** What agents and the Assistant are always told about Hive is much shorter: how to work is in the skills, which load only when they're needed. ### Agents

- **Agent Setup → Codex → Set up** could sometimes not bring up Codex's sandbox prompt: Hive typed `/permissions` while Codex was still busy starting, and Codex queued it. Hive now waits until Codex is idle.
- Hive noticed what a running Codex agent wrote to its rollout (its usage, cost and settings) only about once a minute and at the end of each turn: Windows reported the file's old modified time while Codex kept appending, so Hive now checks the size too.

- **Archive & New** no longer starts a new session when archiving failed.
- Plan usage warnings respect **Settings → Notifications → Desktop notifications**.
- A new Hive skill whose description contains `:` or `#` no longer breaks its front matter, and copying a skill to the workspace checks its folder name.
- Unsaved changes in the Files tab are no longer lost without warning: quitting lists the files and saves or discards them as you choose, reloading or switching workspace offers to save first, deleting warns, and renaming or moving a file keeps its changes.
- Far fewer disk writes while agents work: plan usage is saved only when it changes (at most once a minute), and transcript backups are copied at most once a minute during a turn, plus at the end of each turn.

## 0.1.0 — 29 September 2026

The first public release of Hive. Everything below is what this version does; later releases list what changed.

### Workspaces and projects
- Open or create a workspace; every subfolder is a project.
- `.hive` folders for workspace data (shared notes, skills, MCP servers — meant to be committed) and project data (settings, sessions, backups — excluded from git automatically).
- Mark projects as "working on" to run sessions and get status, without noise from the rest.
- **Compact project list**: collapse the Projects sidebar to a rail of initials and status dots (Ctrl+Alt+B, the chevron, or drag the edge narrow).

### Sessions
- One Claude Code session per project, several running at once, each in its own terminal.
- Live status from Claude Code hooks: ready, working, waiting for input, finished.
- New, resume, stop, archive, rename and adopt sessions started outside Hive. **Stop** is tinted red and **Resume** amber in the project header.
- **Resume per agent**: Resume opens the agent's own last session, and **▾** picks any recent session from its folder; a conversation can only be open in one agent at a time. Each pane shows the name of the session its agent is running.
- **Up to four agents per project**, each in the project folder or in its own git worktree on its own branch, with their own name and optionally their own model, effort and permission mode. Show them one at a time, in two or three columns, or in a grid; one status dot per project in the sidebar.
- **File locks** between agents sharing a folder: an agent that tries to edit a file another agent is editing is told to wait or work on something else (or you're asked, or it's warned — your choice).
- **Worktrees**: Hive creates them next to the workspace, copies `.env` files and runs an optional setup command; review a worktree agent's changes in the Changes and Files tabs and **Merge** them back (squash or merge, conflicts detected before anything changes).
- **Switch permission mode without restarting**: click the mode badge (or Ctrl+Alt+M) and pick one; Hive switches the running session live, and shows the real mode even when you press Shift+Tab in the terminal. Changing the setting offers to switch running agents.
- **Compact** button next to Stop: summarises the conversation so later messages are cheaper, with an optional focus for what to keep. It turns orange, as does the context count in the status bar, when the context passes *Suggest compacting above* (200,000 tokens by default).
- Paste screenshots into a session with Ctrl+V, or drag files from Explorer onto the terminal to paste their paths. Images are kept in the project's `.hive/images` folder.
- Transcript backups so sessions survive Claude Code's cleanup; archived sessions are never deleted.

### Reading and reviewing
- **Sessions** tab: every session of the project with a transcript viewer — the whole conversation including what came before each compaction, thinking and tool calls folded to one line, image thumbnails, live updates for the running session, search across one or all transcripts, copy, export as Markdown and resume.
- **Files** tab: a file browser (create, rename, delete to the Recycle Bin, cut/copy/paste, drag to move, find by name, git status colours, live updates) with an editor and previews for Markdown (with a split view), CSV/TSV, HTML, SVG, images and PDFs.
- **Images** tab: every image sent to the project's sessions, grouped by session.
- **Changes** tab with side-by-side git diffs; **Memory** tab for `CLAUDE.md` and Claude Code's auto memory.
- The lists in the Sessions, Files, Changes and Memory tabs and the Docs view, and the Markdown split view, can be resized by dragging the divider; double-click it to reset.

### Models and usage
- Model setting (global and per project) with the latest of each family, pinned versions, older versions, a custom model ID and **1M context** where the model has one.
- Effort, permission mode, chime and extra arguments per project, each inheriting global defaults. Sessions start in **Auto** permission mode by default. Bypass permissions sits behind an explicit opt-in. Project Settings has categories and search, like Settings.
- Token use, cache state, re-cache estimate, compaction history and API-equivalent cost per session.
- **Plan usage**: the status bar and Overview show how much of your subscription's 5-hour and weekly limits is used, with a notification at 80% and 95% of each. The numbers come from Claude Code; Hive doesn't use your credentials.

### Skills and MCP servers
- Hive skills and MCP servers deployed in the workspace, enabled globally and turned off per project.
- Machine, plugin and local Claude skills listed for reference, with "Copy to workspace".
- Project `.mcp.json` servers detected and kept disabled until copied to the workspace.
- Secret detection for MCP definitions.

### Agent API
- Local HTTP API with bearer-token auth and a server-sent event stream.
- Built-in `hive` MCP server giving agents tools for projects, shared notes, handovers (including the latest handover) and notifications.

### App
- VS Code-style interface with honey-orange accents, dark and light themes.
- Command palette and Go to Project (Ctrl+P), notification centre, searchable settings with tooltips.
- **Configurable keyboard shortcuts** for every command (Settings → Keyboard Shortcuts), with per-project shortcuts for project and session commands, and new defaults for agents, layouts, tabs, compacting and the permission mode.
- Completion chime, Windows notifications and system tray with attention badge.
- A quit dialog that lists running sessions and can wait for agents to finish.
- Claude Code setup: detection, one-click install, update and sign-in. The standalone Claude Code CLI is required; editor-extension copies are not used.
- **Automatic updates** from GitHub releases: checked and downloaded in the background, installed when Hive quits or with **Restart and Update**, never mid-session. The status bar shows progress; Help → Check for Updates; Settings → Updates to check, download and install manually instead, or to get pre-releases.
- Any number of sessions across projects; only the terminals on screen use the graphics card.
